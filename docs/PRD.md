# PRD: 홈케어 고객 앱

## 목표
고객이 필요한 홈케어 서비스를 검색·탐색하고, 상세 정보를 확인한 뒤 바로 전화로 신청할 수 있는 모바일 앱

## 문제 정의
- 홈케어 서비스는 종류가 많고 가격이 불투명해 고객이 어디서 찾아야 할지 모른다
- 신청 경로가 복잡하면 이탈률이 높다 — 정보 확인부터 신청까지 최대 3단계 안에 끝내야 한다
- 고객이 "이 서비스를 왜 해야 하는지" 모르면 가격을 봐도 결정을 못 한다

## 사용자

### 주요 타깃
- 가정 내 가전·주거 관리가 필요한 일반 소비자
- 스마트폰 사용 성인, 주로 30~60대
- 디지털 기기에 익숙하지 않을 수 있음 → 텍스트 크기·버튼 크기에 여유를 준다
- 앱을 처음 열었을 때 즉시 서비스 목록을 볼 수 있어야 한다 (온보딩·로그인 없음)

### 사용자 시나리오

**시나리오 A — 특정 서비스를 이미 알고 있는 경우**
> 김씨(45세)는 에어컨에서 냄새가 나기 시작했다. "에어컨 클리닝" 이라는 서비스가 있다는 걸 알고 있다. 앱을 열어 검색창에 "에어컨"을 입력하고, 가격과 진행방식을 확인한 뒤 전화를 건다.

**시나리오 B — 어떤 서비스인지 모르는 경우**
> 박씨(52세)는 세탁기에서 이상한 냄새가 나는데 어떻게 해야 할지 모른다. 카테고리에서 "가전 클리닝"을 탭하고 목록을 스크롤하다가 "세탁기 클리닝"을 발견한다. 상세 페이지에서 "왜 해야 하는지" 설명을 읽고 납득해 전화를 건다.

**시나리오 C — 이사 직후 여러 서비스가 필요한 경우**
> 이씨(38세)는 이사 후 에어컨 이전 설치, 세탁기 설치가 필요하다. "이전·설치" 카테고리를 탭해 두 서비스를 각각 확인하고, 각 서비스 상세 페이지에서 전화를 건다.

## 내비게이션 구조

```
앱 시작 (스플래시)
    └─→ 하단 탭 바
          ├─ [홈] ─────────────→ 홈 화면
          │                          └─→ 서비스 카드 탭
          │                                └─→ 서비스 상세 페이지
          │                                      └─→ 신청하기 버튼
          │                                            └─→ ConfirmModal
          │                                                  └─→ 전화 앱
          │                                                        └─→ (통화 후) 앱으로 복귀
          └─ [검색] ───────────→ 검색 화면
                                    └─→ 검색 결과 카드 탭
                                          └─→ 서비스 상세 페이지 (동일)
```

**화면 간 이동 규칙**
- 홈 → 상세: `router.push('/service/[id]')` (뒤로가기 가능)
- 검색 → 상세: `router.push('/service/[id]')` (뒤로가기 시 검색 결과로 복귀)
- 상세 → 홈(빈 상태): `router.replace('/')` (뒤로가기 스택 없애고 홈으로)
- 탭 전환: `router.replace` (탭 간 이동 시 히스토리 스택 초기화)

## 핵심 기능 및 UX 명세

### 화면 0: 앱 시작 (스플래시)
- 스플래시 이미지: 앱 아이콘 + 앱명 ("홈케어") 가운데 정렬
- 배경: #0064D2 (브랜드 블루)
- 폰트 로드 완료 후 자동으로 홈 화면으로 전환
- `SplashScreen.preventAutoHideAsync()` → 폰트 로드 완료 시 `SplashScreen.hideAsync()`

### 화면 1: 홈 화면 `/(tabs)/index`

**레이아웃 (위 → 아래)**
```
┌─────────────────────────────┐
│  [앱 로고/이름]  홈케어      │  ← 상단 헤더 (42px 높이)
├─────────────────────────────┤
│  인기 서비스                 │  ← 섹션 제목
│  [카드] [카드] [카드]  →    │  ← 가로 스크롤 FlatList (horizontal)
├─────────────────────────────┤
│  [전체] [가전클리닝] [홈클리닝] [이전설치]  │  ← 카테고리 탭
├─────────────────────────────┤
│  서비스 카드                 │
│  서비스 카드                 │  ← 세로 FlatList
│  서비스 카드                 │
│  ...                        │
└─────────────────────────────┘
│  [🏠 홈]    [🔍 검색]       │  ← 하단 탭 바
└─────────────────────────────┘
```

**UX 세부 명세**
- 헤더: 왼쪽 "홈케어" 텍스트 로고 (22px bold). 별도 네비게이션 헤더 없음 (커스텀)
- 인기 서비스 섹션: `isPopular: true` 인 서비스만 수평 스크롤로 표시. 카드 폭 160px 고정
- 인기 서비스가 없으면 섹션 자체 숨김
- 카테고리 탭: "전체" 탭 포함 4개. 기본 선택: "전체"
- "전체" 탭: 모든 서비스 표시
- 카테고리 탭 가로 스크롤 가능 (ScrollView horizontal) — 탭이 많아져도 대응
- 세로 서비스 목록: 선택된 카테고리에 해당하는 서비스만 표시
- 서비스 목록 하단에 80px 여백 추가 → 하단 탭 바에 가려지지 않도록

### 화면 2: 검색 화면 `/(tabs)/search`

**레이아웃 (위 → 아래)**
```
┌─────────────────────────────┐
│  🔍 [어떤 서비스가 필요하세요?]  │  ← 검색 입력 필드 (포커스 시 키보드 올라옴)
├─────────────────────────────┤
│  (검색어 없을 때)            │
│  💡 인기 검색어             │
│  에어컨  세탁기  냉장고      │  ← 추천 키워드 칩
├─────────────────────────────┤
│  (검색어 있을 때)            │
│  결과 N건                   │
│  서비스 카드                 │
│  서비스 카드                 │
│  ...                        │
│  (결과 없을 때)              │
│  🔍 "OOO"에 맞는 서비스가   │
│  없습니다                   │
│  [전체 서비스 보기]          │
└─────────────────────────────┘
│  [🏠 홈]    [🔍 검색]       │
└─────────────────────────────┘
```

**UX 세부 명세**
- 검색 탭 진입 시 자동으로 키보드 올라오지 않음 — 사용자가 직접 탭해서 열기
- 검색어 없을 때: 추천 키워드 칩 표시 ("에어컨", "세탁기", "냉장고", "청소", "이사")
- 추천 키워드 칩 탭 시: 해당 키워드로 즉시 검색 실행
- 검색어 있을 때: 입력 필드 오른쪽에 X 버튼 노출 → 탭 시 검색어 초기화 + 추천 키워드로 복귀
- 결과 건수: 검색 결과 상단에 "N개의 서비스" 표시
- 키보드가 올라와 있을 때: 결과 목록은 키보드 위에 위치 (KeyboardAvoidingView)
- 결과 카드 탭 시: 키보드 먼저 닫히고 상세 페이지로 이동
- 검색어 80자 초과 입력 불가 (`maxLength={80}`)

### 화면 3: 서비스 상세 페이지 `/service/[id]`

**레이아웃 (위 → 아래, 스크롤)**
```
┌─────────────────────────────┐
│ ← [카테고리명]               │  ← 네비게이션 헤더 (뒤로가기)
├─────────────────────────────┤
│  에어컨 클리닝 (벽걸이)      │  ← 서비스명 (24px bold)
│  가전 클리닝 · 약 1시간      │  ← 카테고리 · 소요시간
├─────────────────────────────┤
│  143,000원~                  │  ← 가격 (28px bold #0064D2)
│  제품 사양에 따라 상이        │  ← 요금 주석 (12px #777)
├─────────────────────────────┤
│  ✓ 전문가 직접 방문          │
│  ✓ 고압 스팀 분해 클리닝     │  ← 핵심 혜택 3개
│  ✓ 서비스 후 1년 수리 보증  │
├─────────────────────────────┤
│  왜 지금 해야 할까요?        │  ← 섹션 제목
│  에어컨 내부 세균은...       │  ← reason 텍스트
├─────────────────────────────┤
│  어떻게 진행되나요?          │  ← 섹션 제목
│  1 예약 확인                 │
│  |                           │
│  2 전문가 방문               │  ← 단계별 스텝
│  |
│  3 분해 청소                 │
│  |
│  4 완료 확인                 │
├─────────────────────────────┤
│  🛡 보증 안내                │  ← warranty 있을 때만
│  서비스 후 1년간 가전 수리... │
├─────────────────────────────┤
│  (하단 CTA 버튼 높이만큼 여백)│
└─────────────────────────────┘
│  📞 신청하기                 │  ← 고정 하단 버튼
└─────────────────────────────┘
```

**UX 세부 명세**
- 네비게이션 헤더: 뒤로가기 `←` 버튼 + 제목은 카테고리명 (서비스명은 아래 본문에 크게 표시)
- 스크롤 시 헤더는 고정 유지, CTA 버튼도 고정 유지
- 스크롤 콘텐츠 하단: CTA 버튼 높이(80px) + SafeArea 만큼 패딩 추가 → 버튼에 가려지지 않도록
- 가격이 "별도 견적"인 경우: 파란색 강조 없이 일반 검정 텍스트로 표시
- warranty 없는 서비스: 보증 섹션 전체 숨김 (빈 공간 없이)
- 전화 후 앱으로 돌아왔을 때: ConfirmModal은 닫힌 상태. 상세 페이지 그대로 유지

### 컴포넌트 4: ConfirmModal

**레이아웃**
```
┌──────────────────────────┐
│                          │
│  📞                      │  ← 전화 아이콘 (32px, 가운데)
│                          │
│  에어컨 클리닝 (벽걸이)  │  ← 서비스명 (18px bold, 가운데)
│  신청 전화를 연결할까요? │  ← 안내 문구 (14px, 가운데)
│                          │
│  ┌──────┐  ┌──────────┐  │
│  │ 취소 │  │  전화하기 │  │  ← 버튼 2개
│  └──────┘  └──────────┘  │
│                          │
└──────────────────────────┘
```

- 배경 오버레이: rgba(0,0,0,0.5)
- 모달 카드: 흰색, border-radius 16, 수평 패딩 32
- [취소]: 배경 #F0F1F4, 텍스트 #444444
- [전화하기]: 배경 #0064D2, 텍스트 #FFFFFF
- 두 버튼은 가로 동일 비율 (flex: 1)

## 핵심 기능 명세

### 1. 서비스 탐색
- 카테고리 탭: 전체 / 가전 클리닝 / 홈 클리닝 / 이전·설치 (4개, 가로 스크롤 ScrollView)
- 홈 화면 최초 진입 시 "전체" 탭 선택 상태
- "전체" 탭: 카테고리 구분 없이 모든 서비스 나열
- 인기 서비스 섹션: 전체 탭일 때만 표시. 다른 카테고리 탭 선택 시 숨김
- 카테고리 탭 전환 시 서비스 목록 스크롤 위치 맨 위로 초기화
- 홈 탭 재클릭 시 스크롤 위치 맨 위로 초기화 (scrollToTop)

### 2. 키워드 검색
- 검색 대상 필드: `name`, `category`, `keywords`
- 검색 방식: 한글 포함(includes) 부분 일치, 대소문자 무시
- 한글 자모 분리 검색은 MVP에서 미지원
- 검색 결과 없음: 안내 문구 + 추천 키워드 칩 + "전체 서비스 보기" 버튼
- 검색어 지울 시: 추천 키워드 표시로 복귀
- 검색어 최대 길이: 80자

### 3. 서비스 상세 페이지
- 정보 표시 순서: 서비스명 → 가격 → 혜택 → 이유 → 진행방식 → 보증
- 스크롤 시 하단 CTA 버튼 항상 고정
- 콘텐츠 하단에 CTA 버튼 높이 + SafeArea 만큼 패딩 추가 (콘텐츠 가려짐 방지)
- 없는 서비스 id: EmptyState + 홈으로 가기 버튼

### 4. 신청 (전화 연결)
- CTA 버튼: 상세 페이지 하단 고정, 항상 보임
- 탭 → ConfirmModal 노출
- ConfirmModal [전화하기] → makeCall() → 전화 앱 실행
- 전화 후 앱 복귀: 모달 닫힌 상태, 상세 페이지 그대로
- 통화 불가 기기: CTA 버튼 유지하되, 탭 시 번호 표시 Alert

## 인터랙션 명세

### 터치 피드백
- 서비스 카드: `activeOpacity={0.7}` (Pressable)
- CTA 버튼: `activeOpacity={0.85}`
- 카테고리 탭: `activeOpacity={0.7}`
- 모달 버튼: `activeOpacity={0.8}`
- 추천 키워드 칩: `activeOpacity={0.7}`

### 스크롤
- 홈 서비스 목록: FlatList (세로). 탭 전환 시 `scrollToOffset({ offset: 0 })` 호출
- 인기 서비스: FlatList (가로, `horizontal`). 스냅 없음
- 카테고리 탭: ScrollView (가로). 선택된 탭으로 자동 스크롤 (scrollTo)
- 상세 페이지: ScrollView. 하단 contentContainerStyle에 CTA 높이 패딩

### 키보드
- 검색 화면: `KeyboardAvoidingView` 적용 (behavior: iOS는 'padding', Android는 'height')
- 검색 결과 카드 탭 시: `Keyboard.dismiss()` 후 상세 페이지 이동
- 상세 페이지: 키보드 불필요, `KeyboardAvoidingView` 미사용

### 전화 후 복귀
- iOS: 홈 버튼 또는 스와이프 업으로 앱 전환 → AppState 'active' 시 아무 동작 없음
- Android: 전화 앱에서 뒤로가기 → 앱으로 자동 복귀

## 전화번호 스펙
- 전화번호는 `data/services.ts` 각 서비스 객체의 `phone` 필드에 관리
- 서비스별로 다른 번호 가능 (추후 부서별 번호 분리 대비)
- 저장 포맷: 하이픈 없는 숫자만 (예: `"15880000"`)
- 표시 포맷: `formatPhone()` 함수로 "1588-0000" 변환
- phone 필드가 비면: 신청하기 버튼 비활성화 (disabled) + 회색 처리

## 비기능 요건

### 성능
- 앱 초기 로딩: 2초 이내 (정적 데이터이므로 네트워크 없음)
- 검색 결과 반영: 타이핑 즉시 (debounce 없음, 20개 미만 데이터셋)
- 화면 전환: 네이티브 애니메이션 기본값 사용

### 접근성
- 모든 터치 요소 최소 크기 44×44pt (iOS HIG 기준)
- `accessibilityLabel` 필수 적용 대상:
  - 서비스 카드: `"에어컨 클리닝 벽걸이, 143,000원부터"` 형태
  - CTA 버튼: `"에어컨 클리닝 신청하기, 전화 연결"`
  - 카테고리 탭: `"가전 클리닝 카테고리"`
  - 모달 [전화하기]: `"전화 연결 확인"`
  - 모달 [취소]: `"전화 연결 취소"`
- Dynamic Type 지원: `allowFontScaling` 기본값(true) 유지

### 오프라인
- 정적 데이터이므로 인터넷 연결 불필요
- 오프라인 상태 별도 처리 없음

### 플랫폼
- iOS 15.0 이상
- Android 10 (API 29) 이상

## 에러 케이스 전체 목록

| 케이스 | 발생 조건 | 처리 방법 |
|-------|----------|----------|
| 서비스 id 없음 | `/service/없는id` 접근 | EmptyState "서비스를 찾을 수 없어요" + 홈으로 버튼 |
| 검색 결과 없음 | 매칭 서비스 0건 | EmptyState + 추천 키워드 + 전체 보기 버튼 |
| 전화 연결 실패 | `Linking.openURL` reject | Alert 번호 직접 표시 |
| 통화 미지원 기기 | `canOpenURL` false | Alert 번호 표시 |
| phone 필드 비어있음 | 데이터 오류 | CTA 버튼 비활성화 + 회색 처리 |
| 데이터 없음 | `services.ts` 빈 배열 | EmptyState "서비스 준비 중" |
